kronosfix_server.dll  —  SERVER-side plugin (dedicated host)
============================================================

Notes
=============
Fixes the ~3-day dedicated-server FREEZE (the long-standing "server locks up
after a few days of uptime" bug). Root cause is a 25-year-old floating-point
precision limit in the sim clock, NOT a memory leak.

Install (if not part of a distribution package)
=============
Drop kronosfix_server.dll in this Plugins\ folder and add to
Plugins\Scripts\PluginLoader.cs (under the dedicated/server block):

    $PluginLoader::kronosfix_server = true;

On load it logs to kronosfix_server.log. When a rebase fires you'll see e.g.:
    rebase: t=... shift=... events=... -> clock=... timeBase=...
(NOTE: kronosfix_server_30stest.dll is a TEST build that rebases every 30s to
prove the mechanism live — do NOT ship it; use the real kronosfix_server.dll,
which rebases at a multi-hour threshold. Delete the test build after verifying.)

The bug
=============
The sim clock is a 32-bit float counting seconds since server start. As it grows,
the gap between representable float values (the ULP) widens. Kronos schedules
events at 10ms (0.01s) granularity. At ~2^18 seconds (~3.03 days) the float ULP
(0.03125s) exceeds 0.01s, so `now + 0.01 == now` -> the scheduler can never reach
the next event time -> infinite loop -> freeze.

How it works
=============
Hooks the server loop's advanceToTime call (FUN_004ebb2f). Once the clock passes
a threshold, it REBASES: subtracts a fixed delta from the current time, the target
time, AND every queued event's time, then bumps the time base by the same delta.
Net effect: the clock is shifted back down into the high-precision float range
while every event keeps the same RELATIVE timing, so nothing observable changes -
it just never hits the precision wall. (A clean source-level fix also exists in
TribesSource: SimManager::rebaseTime + SimEventQueue::rebaseTime, see
re/freeze_fix_13.md / re/server_freeze_rundown.md.)

v2 — MONOTONIC getSimTime() (fixes ALL script timestamp logic at once)
=============
v1's rebase made getSimTime() a saw-tooth (1..3600 hourly), which broke every script that
stores an absolute timestamp: deltas went NEGATIVE for up to an hour after a rebase (the
Server::onClientConnect "recently freed -2529.83s ago" warning, AI.cs "[SPAWN DANGER]"),
and any "until = getSimTime()+cooldown" stored in the last <cooldown> seconds of an hour
landed ABOVE 3600 — unreachable forever = gates wedged until restart (the 3-day
"can't cast / stations busy / world-save pump stuck" rot).

v2 fixes this at the source: on its first hook call it RE-REGISTERS the console command
"getSimTime" (CMDConsole re-registration replaces the entry — verified in TribesSource
consoleInternal.cpp) with a handler returning engineClock + accumulatedRebaseShift. Scripts
now see a MONOTONIC clock across rebases; every stored-timestamp compare just works. The
ENGINE clock/event queue stays bounded exactly as before — the freeze fix is unchanged.
Console arithmetic is double, so the growing value is precision-safe for years of uptime.
The log gains "accum=" on each rebase line plus a one-time "getSimTime shadowed" line.

v2.1 — MONOTONIC CLAMP (resetSimTime immunity): the stock console command resetSimTime()
(called by Server::onMissionLoad "to deal with time imprecision") zeroes the engine clock
OUTSIDE the plugin's accounting, which made v2's script clock jump backwards by the clock
value at that moment (seen live: "[SIM REBASE] rebased by 375.5s" + [SPAWN DANGER] aborts,
because ai.cs detectSimRebase under-corrects). v2.1's handler clamps: any backwards movement
of the raw clock — whatever the source — is folded into the accumulator, so the script clock
continues from its high-water mark. Logs "monotonic clamp: raw clock moved back ...s" when
it happens. Scripts need no changes; resetSimTime stays harmless engine-side.
AI.cs AI::detectSimRebase() (the v1 per-array workaround) never triggers anymore and is
harmless to leave in. getIntegerTime() was always integer/monotonic and is untouched.

Layout: sim clock *0x6a841c, timeBase *0x6a8420; SimManager targetTime +0x6c,
eventQueue +0x70 (size +0, array +0xc); SimEvent.time +0xc. Deep notes:
re/server_freeze_rundown.md, re/DLL_RE_MANUAL.md in the Tribes Browser Based project.
